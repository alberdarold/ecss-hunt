Subject: Bug Report: PDF Text Parser Fails on Complex Documents with use_colpali=False

Hi Morphik Team,

We are writing to report a critical bug in the Morphik PDF ingestion pipeline that is preventing us from using your rules-based features on our technical documents.

**Summary of the Issue:**

When ingesting complex, text-based PDF files (specifically, ECSS space standards) with `use_colpali=False`, the ingestion process fails with the error: `'No content chunks (text or image) could be extracted from the document'`.

This effectively means we cannot use text-based features like `NaturalLanguageRule` or `MetadataExtractionRule` on our document corpus, as the alternative (`use_colpali=True`) only extracts page images, which are not processable by the rules engine.

---

**Detailed Investigation and Findings:**

We have conducted a thorough investigation and can confirm the following:

1.  **The PDFs are Text-Based:** We have verified using local libraries (`pdfplumber`) that our source PDFs are not scanned images and contain selectable, extractable text.

2.  **`use_colpali=True` (Default) Extracts Only Images:** When we ingest files using the default visual pipeline (`use_colpali=True`), the process succeeds, but the resulting chunks contain **only image data** (entire pages rendered as large base64 PNGs). No extractable text is returned, which makes it impossible to use text-based features like `NaturalLanguageRule`.

3.  **`use_colpali=False` Fails Consistently:** When we switch to the text-based pipeline by setting `use_colpali=False`, the ingestion consistently fails with the "No content chunks" error for all our ECSS documents.

4.  **Controlled Test Confirms the Root Cause:**
    *   We created a simple "hello world" text file and programmatically generated a basic PDF from it.
    *   We ingested both the `.txt` and the simple `.pdf` file using `use_colpali=False`.
    *   **Both files were ingested successfully.**

**Conclusion:**

The root cause is that Morphik's text-based PDF parser (`use_colpali=False`) works for simple PDFs but **fails on the complex structure, formatting, or font encodings present in our ECSS technical standards documents.** The parser appears to be brittle and lacks the robustness to handle these real-world documents, failing silently on the backend without falling back or providing a more specific error.

**Impact:**

This bug is a major blocker for us, as it prevents the use of your most powerful rules-based features on our primary document set.

We are happy to provide sample ECSS documents for your team to use for debugging. Please let us know how we can assist further.
